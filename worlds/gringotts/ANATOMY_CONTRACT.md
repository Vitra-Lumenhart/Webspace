## Four-layer service contract
I Root of trust: distinct origins for untrusted worlds and trusted account/vault UI; HTTPS; WebAuthn registration and challenge verification with RP ID/origin/user verification checks; random challenges; account recovery and revocation. Authentication is not encryption. No session secrets in URLs or script-readable persistent storage. With no cookies, investigate short-lived memory-only bearer sessions bound to server-side authorization and explicit reauthentication; XSS still threatens active sessions. Do not ship until independently reviewed.
II Persistent services: transactional authoritative ledger (SQLite first candidate), explicit integer amounts, balanced postings, unique request IDs, atomic settlement/nonce consumption, concurrency, rollback, restart, backups and reconciliation. Human/account/world pseudonym/character/session are separate. Personal vault encryption is separate from authoritative estate and public receipts. Client-held encryption keys, AEAD, unique nonces per key, authenticated version/context, key rotation/recovery tradeoffs, authenticated distribution of client code. No plaintext or keys in logs. No claim of zero knowledge for metadata or compromised clients.
III Delegated authority: independent issuer/world/witness keys, audience, subject, scope, expiry, nonce, version; signed canonical format with maintained library, algorithm allowlist and key identifier; verifier checks action, audience, current time, revocation and durable single-use where relevant. Consent record: recipient, fields, purpose, lifetime, revocation, consequences, alternative; previously learned data may persist. Pairwise pseudonyms; do not equate guest status with consent. No universal moral score.
IV World interfaces: optional independent adapters, minimal capability request, validated receipt, reconciliation; no direct bank DB or master keys. Vitra roles separate outside LLM: operator sees operational minimum, banker settlement, GM committed game state, witness scoped projections, NPC its own facts, companion entrusted data. Deny by default; never send raw private state to model or log. Fictional theft, deception and simulated exposure only in separate synthetic domains; no real tracking, secrets or intentionally broken production controls.

## Threat and data inventory
For every record declare owner, classification (public / scoped / private / secret), purpose, recipient, storage, transport, retention, deletion, revocation, authority and metadata exposure. Threats: copied URLs and referrers, same-origin XSS and malicious dependencies, server/operator access, replay, stale or concurrent writes, cross-world confusion, compromised endpoint, recovery abuse, loss of keys, metadata inference, prompt injection, insecure backups and deceptive consent. Controls: separate origins/processes/keys, strict CSP and dependency integrity, redacted logs, minimized event projections, access checks on every request, transaction uniqueness, least privilege, independent review. Public code is not evidence of matching deployment.
Data: account ID private (auth service); pairwise world ID scoped (specific world); arrival tag public; session credential secret (memory only proposed); vault ciphertext private (storage service); vault key secret (owner client); ledger entries scoped (bank and authorized party); public receipts opt-in/redacted; Vitra observations explicitly scoped; retention and recovery periods TBD before pilot.

## Versioned logical interfaces (not deployed endpoints)
Register/authenticate -> account principal; requestCapability(principal, audience, action, amount, expiry, consentId) -> limited grant; settle(grant, transactionId, postings) -> receipt; witness(eventId, permissionId) -> minimal projection; revoke(consentId or credentialId) -> future access denied; vaultPut(ciphertext, envelopeVersion, keyId) -> storage receipt. Never trust caller-provided role, balance, timestamp or identity. Validate schemas, sizes, versions and unknown fields; reject unsupported versions. No raw master key transfer. Separate bank, world and witness signer. No unreviewed cross-world migration.

Static GitHub Pages can host lab only, not authoritative service. Backend host and recovery policy unselected.
 
## Evidence boundaries
Lab is memory-only, no network requests, no cookies, no browser storage, no user-entered private data, no actual crypto or trusted execution. Role toggles are illustrations. Fourteen exposure cases are conditional examples, not a universal ranking. No historical test rerun, no full 3D integration, no production server or browser tests in this draft. Historical ledger and paused estate checkpoint preserved.
